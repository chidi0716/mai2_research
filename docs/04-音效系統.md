# 04 音效系統（CRI ADX2）

## 檔案格式

| 檔案 | 內容 |
|---|---|
| `.acb`（Cue Sheet） | 目錄：音效名稱、編號、序列 / 音軌 / 合成設定、聲音的索引。內部是 CRI 的 `@UTF` 表格格式。也可能**內嵌**一份音訊庫（memory AWB） |
| `.awb`（Wave Bank） | 音訊庫：AFS2 格式，裡面是一段段壓縮音訊（ADX 或 HCA）。通常放比較長、要串流播放的聲音（stream AWB） |

`.acb` 裡的 `StreamAwbHash` 記錄了配對 `.awb` 的 MD5，可以用來確認兩個檔案是不是同一組。

### `Mai2Cue`（遊戲主要音效庫）

實際解析（冰冰冰版的 `Mai2Cue.acb`，53MB，內嵌 444 段聲音；配對的 `Mai2Cue.awb` 23MB，443 段）：

- **488 個音效（Cue）**，編號 0～543（不連續），名稱例如 `SE_GAME_ANSWER`、`BGM_ENTRY`、`JINGLE_GAMEOVER`
- 分類（名稱前綴）：`SE_GAME` 212、`SE_RESULT` 46、`SE_MAP` 37、`SE_KALEID` 33、`SE_EMONEY` 20、`SE_ENTRY` 15、`SE_SYS` 12、`BGM_*` 13、`JINGLE_*` 16…
- `SE_GAME_BREAK_01_000001`～`_000050` 這類大量編號的音效，對應遊戲設定裡可以選的音效組
- 歌曲本身、角色語音不在 `Mai2Cue`，在其他音效庫

## 從「音效」找到「聲音」

一個 Cue 不一定直接對應一段聲音，中間可能有好幾層：

```
CueTable[CueId]
  ReferenceType / ReferenceIndex
    1 = Waveform（直接是一段聲音）
    2 = Synth   → ReferenceItems: (type, index) 清單，可再指向 Waveform / Synth / Sequence
    3 = Sequence→ TrackIndex 清單 → TrackTable[i].EventIndex → TrackEventTable 的 Command
                   Command 裡 code 2000（noteOn）帶 (type, index)，再往下解析
WaveformTable[i]
  Streaming: 0 = 內嵌 memory AWB、1 = stream AWB、2 = 兩者
  MemoryAwbId / StreamAwbId → AWB 裡的第幾段
  EncodeType: 0 = ADX、2 = HCA
```

例：`SE_GAME_ANSWER`（正解音）= CueId 88 → Sequence → 1 條音軌 → noteOn Synth 50 → Waveform 44 → memory AWB 第 443 段（HCA，44.1kHz 立體聲，17904 取樣 ≈ 0.4 秒）。冰冰冰版就是在內嵌音訊庫最後加了這一段，再把正解音指過去。

`tools/cri/` 裡有完整的解析程式。

## 加密與解碼

`Mai2Cue` 的聲音大多是 **ADX**（開頭 `80 00`），新加的冰冰冰是 **HCA**（開頭 `C8 C3 C1 00`，即 `HCA\0` 每個位元組加上 0x80 的遮罩版本）。兩者都有加密，金鑰相同：

```
7F4551499DF55E68   （maimai DX；出自 vgmstream 公開的 hca_keys.h / adx_keys.h）
```

AWB 標頭的 subkey（AFS2 位移 0x0E）是 0，不需要再衍生金鑰。

### ADX 第 9 型加密（標頭 0x12～0x13 = `04 09`）

每個音框前 2 個位元組是音量係數，和一串由金鑰產生的數字做 XOR：

```python
k = key9 - 1
start = (k >> 27) & 0x7fff
mult  = ((k >> 12) & 0x7ffc) | 1
add   = ((k << 1)  & 0x7fff) | 1

x = start
for 每個音框（依檔案順序, 多聲道交錯也算在同一串）:
    scale = (scale ^ x) & 0x1fff      # 只取低 13 位, 少了這步會變成雜訊
    x = (x * mult + add) & 0x7fff
```

解完把標頭 0x13 改成 0，就是一般 ADX，ffmpeg 可以直接解（`-f adx`）。

### HCA

用 vgmstream 的 `clHCA` 解碼器（單檔 C 程式）配金鑰解碼，`tools/cri/hca2wav.c` 是包裝程式。

> 驗證有沒有解對：雜訊的過零率約 0.5、音量接近滿格；正常音訊過零率通常低於 0.1。

## 在 mod 裡替換音效

遊戲播放音效走 `SoundCtrl.Play(SoundCtrl.PlaySetting)`，`PlaySetting` 有 `AcbID`（第幾個音效庫，`Mai2Cue` 是 0）和 `CueIndex`（音效編號）。

冰冰冰正解音切換的做法：

1. `SoundManager.Initialize` 之後，用 `Singleton<SoundCtrl>.Instance.LoadCueSheet(6, "…/Mods/AnswerSoundSwitch/Ice/Mai2Cue")` 把整套替換音效載入成第 6 號音效庫。
2. 用反射呼叫私有的 `SoundCtrl.GetCueSheet(6)` 拿到 `CriAtomExAcb`，`GetCueInfo("SE_GAME_ANSWER", out info)` 確認 `info.id == 88`，不符合就卸載。
3. Prefix `SoundCtrl.Play`：遇到 `AcbID == 0 && CueIndex == 88` 時改成 `AcbID = 6`。
4. Postfix `CriAtomExPlayer.SetCue(CriAtomExAcb, int)`：這次播放是替換音效時 `SetVolume(1.5f)` 放大音量。

同樣的方法改成一張對照表，就能替換任意多個音效，而且不動遊戲原始檔。另一種做法是直接覆蓋遊戲的 `Mai2Cue.acb/.awb`，簡單但不可逆。

製作新的 ACB/AWB：官方工具 CRI Atom Craft 不公開，社群常用 SonicAudioTools、VGAudio。最穩的做法是複製整套、只換掉要改的那段聲音，序列與參數不動。
