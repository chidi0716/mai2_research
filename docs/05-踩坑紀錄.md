# 05 踩坑紀錄

| # | 問題 | 原因 | 解法 |
|---|---|---|---|
| 1 | `Process` 型別解析錯誤 | 遊戲有全域命名空間 `Process`（`Process.MusicSelectProcess`…），和 `System.Diagnostics.Process` 撞名 | `using Proc = System.Diagnostics.Process;`；遊戲的寫 `global::Process.xxx` |
| 2 | `Monitor` 型別解析錯誤 | 遊戲有命名空間 `Monitor`（`Monitor.MusicSelectMonitor`） | 鎖定用寫完整的 `System.Threading.Monitor` |
| 3 | `Harmony`、`Type` 模稜兩可 | 和遊戲或其他命名空間撞名 | 寫 `HarmonyLib.Harmony`、`System.Type` |
| 4 | 偶發閃退、狀態錯亂 | 在網頁 / 網路執行緒呼叫 Unity API 或遊戲物件 | 外部執行緒只排隊，在 `OnUpdate`（主執行緒）執行；`Application.dataPath`、`FindObjectOfType`、`Time` 也算 |
| 5 | 裝 mod 後**登入時閃退**（`PlInformationProcess.RestoreGhost` 空參考） | mod 從遊戲第一幀就頻繁碰遊戲物件、做重活，干擾遊戲啟動階段的初始化 | **就緒門控**：`DataManager.IsLoaded()` 之前什麼都不做 |
| 6 | 曲目只剩幾首 / 0 首 | 其他 mod 改寫了 `DataManager.GetMusics()`；內部表載入前是空佔位表；`IsDisable()` 把整庫判成停用 | 多路讀取（選曲列表 + 內部表），取條目最多的；整庫被過濾光時自動關掉停用過濾 |
| 7 | 用 Finalizer 吞例外後選曲列表變空 | 遊戲帶著錯誤狀態繼續跑 | 防閃退補丁預設關閉，只在確定需要時開 |
| 8 | 主執行緒卡住，遊戲「沒有回應」 | 主執行緒直接寫網路（SSE），某個客戶端不收資料就一直阻塞 | 每個連線一條寫入執行緒，寫入加逾時；主執行緒只放最新狀態 |
| 9 | 點歌時卡一下 | 每 5 秒整表重掃曲庫、重建 JSON、封面編碼和跳轉擠在同一幀 | 改用便宜的變化偵測、片段快取、跳轉期間暫停重活；加 `/api/perf` 量測 |
| 10 | 點不到 DX 譜 | 用找到的卡片 ID 判斷 DX/STD，DX 行會落到標準卡 | 依使用者點的那套決定 `ScoreType`，難度也用對應類型的 ID 查 |
| 11 | 在難度畫面再點歌後，按返回回不去 | 在難度畫面上直接再切一次難度畫面，「前一個畫面」被記成難度畫面本身 | 先用 `SyncNext(Music)` 退回選曲列表，再切到難度畫面 |
| 12 | 設定的難度被蓋掉 | `CalcMonitorDifficulty` 會依曲子預設值覆寫難度索引 | 先呼叫它，再設定難度 |
| 13 | `isExistsScore` 永遠讀不到 | 1.70 是 `List<bool>`，舊程式用 `as bool[]` | 同時支援 `bool[]` / `List<bool>` / `IList` |
| 14 | 網頁伺服器拒絕外部網域 | Mono 的 `HttpListener` 依 Host 標頭比對前綴 | 隧道設定 `--http-host-header`，或自己的轉發器改寫 Host |
| 15 | 綁不了 IPv6 | Mono 的 `HttpListener` 不支援 IPv6 位址 | 用 `TcpListener` 接 IPv6，再轉給 `HttpListener` |
| 16 | 選曲畫面事件、日誌重複兩次 | `OnStart` / `OnRelease` 按玩家人數各觸發一次 | 比對是否同一個實例 |
| 17 | 不同遊戲版本行為不同 | `Assembly-CSharp.dll` 每版不同 | 關鍵成員用反射加防呆，找不到就停用該功能而不是崩潰；或標明只支援的版本（SHA-256） |
| 18 | 改了 `ServicePointManager` 影響整個遊戲 | 它是整個程序共用的設定 | 下載等網路工作交給外部程式（curl / PowerShell） |
| 19 | 解 ADX 出來是雜訊 | 第 9 型加密解完沒有只取低 13 位 | `(scale ^ xor) & 0x1fff`（見 [04](04-音效系統.md)） |
