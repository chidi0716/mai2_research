# 05 踩坑紀錄

| # | 問題 | 原因 | 解法 |
|---|---|---|---|
| 1 | `Process` 型別解析錯誤 | 遊戲有全域命名空間 `Process`（`Process.MusicSelectProcess`…），和 `System.Diagnostics.Process` 撞名 | `using Proc = System.Diagnostics.Process;`；遊戲的寫 `global::Process.xxx` |
| 2 | `Monitor` 型別解析錯誤 | 遊戲有命名空間 `Monitor`（`Monitor.MusicSelectMonitor`） | 鎖定用寫完整的 `System.Threading.Monitor` |
| 3 | `Harmony`、`Type` 模稜兩可 | 和遊戲或其他命名空間撞名 | 寫 `HarmonyLib.Harmony`、`System.Type` |
| 4 | 偶發閃退、狀態錯亂 | 在網頁 / 網路執行緒呼叫 Unity API 或遊戲物件 | 外部執行緒只排隊，在 `OnUpdate`（主執行緒）執行；`Application.dataPath`、`FindObjectOfType`、`Time` 也算 |
| 5 | 裝 mod 後**登入時閃退**（`PlInformationProcess.RestoreGhost` 空參考） | mod 從遊戲第一幀就頻繁碰遊戲物件、做重活，干擾遊戲啟動階段的初始化 | **就緒門控**：`DataManager.IsLoaded()` 之前什麼都不做 |
| 6 | 曲目只剩幾首 / 0 首 | 其他 mod 改寫了 `DataManager.GetMusics()`；內部表載入前是空佔位表；`IsDisable()` 把整庫判成停用 | 多路讀取（選曲列表 + 內部表），取條目最多的；整庫被過濾光時自動關掉停用過濾 |
| 7 | 用 Finalizer 吞例外後選曲列表變空 | 遊戲帶著錯誤狀態繼續跑 | 防閃退補丁預設關閉，只在確定需要時開 |
| 8 | 主執行緒卡住，遊戲「沒有回應」 | 主執行緒直接寫網路（SSE），某個客戶端不收資料就一直阻塞 | 每個連線一條寫入執行緒，寫入加逾時；主執行緒只放最新狀態 |
| 9 | 點歌時卡一下 | 每 5 秒整表重掃曲庫、重建 JSON、封面編碼和跳轉擠在同一幀 | 改用便宜的變化偵測、片段快取、跳轉期間暫停重活；加 `/api/perf` 量測 |
| 10 | 點不到 DX 譜 | 用找到的卡片 ID 判斷 DX/STD，DX 行會落到標準卡 | 依使用者點的那套決定 `ScoreType`，難度也用對應類型的 ID 查 |
| 11 | 在難度畫面再點歌後，按返回回不去 | 在難度畫面上直接再切一次難度畫面，「前一個畫面」被記成難度畫面本身 | 先用 `SyncNext(Music)` 退回選曲列表，再切到難度畫面 |
| 12 | 設定的難度被蓋掉 | `CalcMonitorDifficulty` 會依曲子預設值覆寫難度索引 | 先呼叫它，再設定難度 |
| 13 | `isExistsScore` 永遠讀不到 | 1.70 是 `List<bool>`，舊程式用 `as bool[]` | 同時支援 `bool[]` / `List<bool>` / `IList` |
| 14 | 網頁伺服器拒絕外部網域 | Mono 的 `HttpListener` 依 Host 標頭比對前綴 | 隧道設定 `--http-host-header`，或自己的轉發器改寫 Host |
| 15 | 綁不了 IPv6 | Mono 的 `HttpListener` 不支援 IPv6 位址 | 用 `TcpListener` 接 IPv6，再轉給 `HttpListener` |
| 16 | 選曲畫面事件、日誌重複兩次 | `OnStart` / `OnRelease` 按玩家人數各觸發一次 | 比對是否同一個實例 |
| 17 | 不同遊戲版本行為不同 | `Assembly-CSharp.dll` 每版不同 | 關鍵成員用反射加防呆，找不到就停用該功能而不是崩潰；或標明只支援的版本（SHA-256） |
| 18 | 改了 `ServicePointManager` 影響整個遊戲 | 它是整個程序共用的設定 | 下載等網路工作交給外部程式（curl / PowerShell） |
| 19 | 解 ADX 出來是雜訊 | 第 9 型加密解完沒有只取低 13 位 | `(scale ^ xor) & 0x1fff`（見 [04](04-音效系統.md)） |
| 20 | 反射找不到成員 | 遊戲本身有拼錯的名稱：`Process.CharacterSelectProces`、`GameScoreList.GetAchivement()`、`deluxscore`、`NotesManager.getPlayFirstMsec`（小寫 g） | 照遊戲的拼法寫；不確定時同時試幾種拼法 |
| 21 | 結算畫面讀到 0 分 / 舊資料 | `ResultProcess.OnStart` 當下成績還沒填好 | 之後幾幀重讀，直到數值不再變化；`IsEnable == false` 的那一側是沒在玩 |
| 22 | 玩家名稱讀到空的或「GUEST / 游客」 | 開機、登出、未登入時的狀態 | 視為沒有名稱，每秒最多重試一次 |
| 23 | 不同版本某個型別不存在，整個 mod 載入失敗 | `[HarmonyPatch(typeof(X))]` 寫死了型別 | 用 `AccessTools.TypeByName` + 手動 `harmony.Patch`，找不到就略過 |
| 24 | 同一個 mod 被載入兩份（新舊檔名並存） | 改名後舊 DLL 還在 `Mods` | 具名 `Semaphore` 防止重複執行；安裝程式負責移除舊檔 |
| 25 | 補丁掛上了卻從來不觸發 | Mono JIT 會內聯很小的方法（例 `AssetManager.GetPartnerTexture2D(string)` 從 `(int)` 版本被呼叫、`InputManager.GetTouchPanelAreaDown`）（NGO 實測） | 掛呼叫端真的用的多載（`GetPartnerTexture2D(int)`），或往下一層掛較大的方法（`IO.TouchPanel.GameInputLog.TriggerOn`） |
| 26 | 每首歌記憶體多約 50 MB、不會釋放 | Mono 的 Boehm GC 沒有 ephemeron，`ConditionalWeakTable` 的 key 被強引用，整個畫面留在記憶體（NGO 實測） | 不用 CWT；改用 instance ID 字典，離開畫面時清掉 |
| 27 | 選曲畫面每十幾秒卡一下 | 每幀補丁裡讀 `Object.name`（每次配置新字串）、組路徑字串，垃圾太多（NGO 實測） | 依 instance ID 快取名稱與路徑，每幀補丁不要配置記憶體 |
| 28 | 歌曲開始第一幀凍住，越玩越久 | `GameProcess.OnStart` 在淡出剛清完後又跑一次 `unloadUnusedAndGC`（反編譯），heap 大時要 1～1.8 秒（NGO 實測） | Prefix `SystemConfig.unloadUnusedAndGC`，距上次不到約 20 秒就略過 |
| 29 | 在 mod 裡模擬按鈕沒反應 | 機台按鈕、Test / Service、刷卡是 `amdaemon.exe` 裡的 segatools 讀的，不經過 `Sinmai.exe`（NGO 實測） | 從 amdaemon 端送鍵（見 [11](11-效能與測試.md#3-模擬按鍵ngo-實測)）；觸控可以從 `GameInputLog.TriggerOn` 注入 |
| 30 | 隱藏店內匹配分類後，NORMAL 模式按 START 卡住 | 略過了 `MusicSelectProcess.PartyExec`，NORMAL 模式靠它把 START 轉成開始打歌（NGO 實測） | 在 `SetConnectData` 之後拿掉分類，`IsConnectStart` / `IsConnectStop` 回「沒變化」，不要略過 `PartyExec` |
| 31 | 改了 Sprite 的 `m_SortingLayer`，進待機畫面就崩潰 | 原因不明（NGO 實測） | 要調整繪製順序改材質 render queue（例 2450）；MeshRenderer 的 sorting layer 改了也沒效果 |
| 32 | 換上的圖顏色髒掉 / 邊緣被裁 | 很多貼圖是白色遮罩，由 `Image.color` 或程式上色；原版 Sprite 網格沿著原圖描邊（NGO 實測） | 貼圖維持白 / 灰，改的是顏色；換形狀時把網格改成整張四邊形或放大 `textureRect` |
| 33 | UnityPy 改 `resources.assets` 後檔案壞掉或修改消失 | UnityPy 是延遲讀取；同一物件第二次讀改存會從原始檔重讀（NGO 實測） | 先 `env.file.save()` 產生完整輸出再寫 `.new`、檢查大小；每個物件每次執行只改一次 |
| 34 | 自訂銘牌 XML 的 `<fileName>` 沒有作用 | `DataManager.LoadPlate` 固定把檔名設成 `NamePlate/UI_Plate_{id:D6}.png`（反編譯） | 圖照這個名稱放 |
| 35 | 選曲畫面沒有「みんなの人気楽曲（POPULAR）」分類，只有 GUEST / 新帳號看得到 | SDEZ 1.70 的程式（IL 已確認；外面機台破萬也看得到，原因未查明）：`MusicSelectProcess.registerMusic` 只在有任何已登入玩家 `Detail.HighestRating < 4000` 時才建立排行榜清單（反編譯 1.70），伺服器有沒有下發排行都一樣 | Prefix `registerMusic` 時暫時把已登入玩家的 `HighestRating` 設成 0，Postfix / Finalizer 還原（未實作驗證） |
