# 11 效能與測試（GC、記憶體、模擬按鍵）

> 來源：反編譯 SDEZ 1.70 `Assembly-CSharp.dll`（標「反編譯」的都核對過）、[maimai-ngo](https://github.com/TOTO-git-q/maimai-ngo) 的說明文件。標「NGO 實測」的是對方記錄的量測結果，我們沒有自己重現。

## 1. 遊戲自己的 GC 時機（反編譯）

- `MAI2System.SystemConfig.unloadUnusedAndGC()` = `Resources.UnloadUnusedAssets()` + `GC.Collect()`。`FadeProcess`、`BlackoutFadeProcess` 每次淡出都會呼叫。
- `GameProcess.OnStart`：再呼叫一次 `unloadUnusedAndGC()`，然後 `GarbageCollector.GCMode = Disabled`（譜面確認 / 影片確認模式除外）。
- `GameProcess.OnRelease`：`GCMode = Enabled` 後 `GC.Collect()`。
- 另有私有的 `GameProcess.ForceGC()`（打開、Collect、再關掉）。
- `AdvertiseProcess`、`EntryProcess`、`PlInformationProcess`、`CollectionProcess` 也各有 `GC.Collect()`。

意思是：**打歌中不會有 GC**，打歌中的卡頓不是 GC 造成的。停頓集中在歌曲開始（讀譜面、影片）、淡入淡出、進結算那一下。

## 2. Mono（Unity 2018.4）的記憶體特性（NGO 實測）

- Mono 用的是 **Boehm GC**：不分代，每次回收都掃整個 heap。heap 越大，之後每次回收越慢。
- 歌曲開始那次 `unloadUnusedAndGC` 在長時間遊玩後可以到 1～1.8 秒（第一幀凍住）。NGO 的做法是 Prefix 它，距離上次執行不到 20 秒就略過，讓清理只發生在淡出的時候。
- 結算畫面開頭約 0.75 秒的一幀是 `OnRelease` 的 `GC.Collect`，屬於遊戲本身的設計。
- **不要用 `ConditionalWeakTable`**：Boehm 沒有 ephemeron，key 會被強引用。NGO 兩個 CWT 讓每個結束的選曲 / 結算畫面都留在記憶體裡，每首歌 +約 50 MB。改用「instance ID → 資料」的字典，離開畫面時清掉。
- `UnityEngine.Object.name` 每讀一次就配置一個新字串。`Image` 的 `sprite` setter、`OnEnable`、`OnPopulateMesh` 這類補丁每幀會跑很多次，要依 instance ID 快取名稱。他們在選曲畫面每幀組路徑字串，結果每約 11 秒卡 110～185 ms。
- `FindObjectsOfTypeAll` 本身就會造成卡頓，只能在測試時用。
- 離開畫面（視窗移到螢幕外）時遊戲約 30 fps：在螢幕外只看記憶體成長，卡頓要在正式畫面上量。

### 量測方式

- 每首歌一行：`GameProcess.OnStart` / `OnRelease` 之間數幀數、超過 25 / 50 ms 的幀數、最慢一幀、開頭 3 幀（讀取）時間、`GC.CollectionCount(0)` 差值。
- 每次清理一行：`unloadUnusedAndGC` 花的時間 + 之後的 `GC.GetTotalMemory(false)`。
- 健康的樣子：清理後的 heap 和行程記憶體在 20 首以上都持平；每首歌漲幾十 MB 就是洩漏。

## 3. 模擬按鍵（NGO 實測）

- 機台按鈕、Test / Service、刷卡都**不是 `Sinmai.exe` 讀的**，而是 `amdaemon.exe` 裡的 segatools `mai2hook.dll` / `hinata.dll` 用 `GetAsyncKeyState` 讀，而且只在 `GetForegroundWindow()` 是遊戲視窗時才收。
  - 所以在 mod 裡掛 `UnityEngine.Input` 或遊戲的 `InputManager` 模擬不了按鈕。
  - 要在背景送鍵，得在 amdaemon 改這兩個 import（他們寫了一個 x64 stub 把 `GetAsyncKeyState` 指向自己的按鍵表、`GetForegroundWindow` 回傳遊戲視窗）。
  - 放開後要等約 1 秒再還原 import，不然最後一個鍵會卡住（確認鍵失靈）。
- segatools 預設鍵位：Enter 按住 3 秒 = 刷卡（`DEVICE\aime.txt`）；`W E D C X Z A Q` = 按鈕 1～8（從右上順時針，C = 按鈕 4 = 確認 / START）；F1 Test、F2 Service、F3 投幣。
- 觸控用 `IO.TouchPanel.GameInputLog.TriggerOn(uint side, InputManager.TouchPanelArea)` 注入比較穩，`InputManager.GetTouchPanelAreaDown` 太小，會被 JIT 內聯（見 [10](10-資源與選項包.md#3-貼圖怎麼載入)）。

### 測試時要注意的事（NGO 實測）

- 待機畫面按任何按鈕都會開始 GUEST 遊玩，只能刷卡。登入要在 `EntryProcess` 按 C 確認；註冊過的卡可能要刷第二次。
- 功能票畫面按 C 會用掉票。
- 模式選擇按太慢（約 7 秒一次）會逾時，約 2.5 秒一次可以。
- AquaMai `DisableTimeout` + `ForceAsServer` 時，NORMAL 模式的店內匹配倒數不會結束，START 後會一直等；自由模式沒有這個等待。
- 強制結束遊戲會跳過結束時的上傳，這次遊玩的成績會不見。要用 AquaMai `OneKeyEntryEnd`（選曲時長按 Service）正常結束。
- 假造帳號狀態的測試（例如「從沒玩過」）要把所有可能被改到的欄位還原再上傳。他們上傳時漏還原 `CharaSlot`，結果真實帳號的隊伍被蓋掉。
