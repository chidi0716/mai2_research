# 03 遊戲內部結構

以下名稱來自反編譯 `Assembly-CSharp.dll`（1.70 前後版本），不同版本可能有差異。

## 畫面架構：Process 與 Monitor

- 遊戲流程由一連串 **Process**（例如 `MusicSelectProcess` 選曲、`PlInformationProcess` 登入資訊、打歌、結算…）組成。
- 每個玩家（1P / 2P）的畫面是一個 **Monitor**（例如 `MusicSelectMonitor`），Process 的 `MonitorArray` 裡有每個玩家的 Monitor。
- 一個 Process 內部再分**子畫面（SubSequence）**，各玩家各自記錄目前在哪個子畫面。
- 全部畫面的型別名稱一覽、打歌中的判定、成績、倒數計時、版本與玩家名稱的讀法見 [09](09-遊戲流程與狀態讀取.md)。

### 選曲畫面 `MusicSelectProcess`

子畫面編號（`MusicSelectProcess.SubSequence`）：

| 值 | 名稱 | 畫面 |
|---|---|---|
| 0 | Music | 選曲列表 |
| 1 | Genre | 分類 |
| 2 | SortSetting | 排序設定 |
| 3 | Difficulty | 難度選擇 |
| 4 | UtageDifficulty | 宴會場難度 |
| 5 | Menu | 選單 |
| 6 | Option | 選項 |
| 7 | Character | 角色 |

常用成員：

| 成員 | 說明 |
|---|---|
| `CombineMusicDataList` | 選曲列表：`List<ReadOnlyCollection<CombineMusicSelectData>>`，外層是分類、內層是該分類的曲目卡 |
| `CurrentCategorySelect` / `CurrentMusicSelect` | 目前的分類 / 曲目游標 |
| `ScoreType` | `ConstParameter.ScoreKind`：0 = 標準（STD）、1 = DX |
| `CurrentDifficulty[p]` / `DifficultySelectIndex[p]` | 每個玩家的難度（顯示用 / 難度條位置） |
| `ChangeBGM()` | 依目前曲目換預覽音樂 |
| `CalcMonitorDifficulty(bool)` | 依曲目重算畫面資料；**會覆寫難度**，所以要在設定難度之前呼叫 |
| `SyncNext(SubSequence)`（私有） | 遊戲自己切子畫面：重置目前子畫面、記住前一個、所有玩家一起切 |
| `SetInputLockInfo(p, ms)` / `IsInputLocking(p)` | 鎖定 / 查詢玩家輸入（切畫面動畫期間會鎖） |
| `IsUtageMusicFolder()`、`IsGhostFolder(p)`、`IsConnectionFolder()`、`IsChallengeFolder()`、`IsTournamentFolder()`、`IsExtraFolder(p)` | 目前分類是不是宴會場 / 對戰 / 聯機 / 挑戰 / 段位等特殊資料夾 |

私有欄位：`_subSequenceArray`（`SequenceBase[][]`，[玩家][子畫面]）、`_currentPlayerSubSequence`、`_beforePlayerSubSequence`、`_mainSequence`（遊戲私有列舉，外部只能反射讀成 int）。

### 遊戲自己「確認選曲」的流程

反編譯 `MusicSelectSequence` 看到，玩家在選曲列表按確認時，遊戲對每個玩家做：

```csharp
monitor.ChangeButtonImage(InputManager.ButtonSetting.Button04, 14);
monitor.SetScrollMusicCard(false);
monitor.OutGenreTab();
SetInputLockInfo(player, 1200f);
// 之後
SyncNext(isUtage ? SubSequence.UtageDifficulty : SubSequence.Difficulty);
```

要讓 mod 跳歌後自動進難度畫面，照這個流程做最安全（點歌台就是這樣做）。

## 曲目與譜面資料

### `DataManager`

- `Singleton<Manager.DataManager>.Instance`，`IsLoaded()` 判斷資料是否載入完。
- 公開 API `GetMusics()` / `GetMusic(id)` 會被其他 mod（MuNET / AquaMai 一類）用 Harmony 改寫成伺服器下發的曲目，**結果可能不完整**。要全量曲目時改讀內部表（例如私有欄位 `_musics`）或選曲列表。
- 內部表在載入完之前是「非 null 的空佔位表」（`CreateDummyTable<T>()`），不能只用 null 判斷有沒有資料。
- 其他常見方法：`GetMusicGenre(id)`、`GetUdemaeBoss(id)`（段位 BOSS，資料缺漏時會回 null → 遊戲閃退的來源之一）。

### `MusicData`（一首歌）

| 成員 | 說明 |
|---|---|
| `GetID()` | 曲目 ID |
| `name.str` / `artistName.str` | 曲名 / 藝術家 |
| `genreName`（`.str` / `.id`） | 分類 |
| `bpm`、`AddVersion.str` | BPM、加入版本 |
| `notesData` | 譜面列表 |
| `IsDisable()` / `disable` | 是否停用（個別資料下 `IsDisable()` 會把整庫判成停用，要搭配欄位值判斷） |
| `jacketFile` / `thumbnailName` | 封面資源名 |
| `utageKanjiName` | 宴會場的漢字（宴、協、狂…）；宴會場判斷見 [09](09-遊戲流程與狀態讀取.md) |

### `Notes`（一個難度的譜面）

| 成員 | 說明 |
|---|---|
| `isEnable` | 有沒有這個難度 |
| `level` / `levelDecimal` | 等級整數 / 小數；**定數 = level + levelDecimal / 10**（例如 13 + 0.7 = 13.7） |
| `notesDesigner.str` | 譜師 |
| `musicLevelID` | 顯示用等級的 ID → `DataManager.GetMusicLevel(id).levelNum`（例如 `13+`） |

> 難度要看 `notesData` 的**位置**（0 = BASIC、1 = ADVANCED、2 = EXPERT、3 = MASTER、4 = Re:MASTER），不是看 `notesType`（部分資料包裡全都是 0）。位置也對應譜面檔名，例如 `015001_03.ma2` = MASTER。

### DX 與標準譜

- 同一首歌在選曲列表**只有一張卡**，DX / 標準靠 `ScoreType` 切換。
- DX 版曲目 ID 通常是標準版 + 10000（例如 1234 / 11234），但有例外（例如 Trust：695 / 11726），找不到時要用曲名比對。
- 要指定 DX 譜，必須依「使用者點的是哪一套」決定 `ScoreType`；用找到的卡片 ID 判斷會永遠落在標準譜。

## 其他

- `GameManager`（靜態）：`SelectMusicID`、`SelectDifficultyID[]`、`CurrentDifficulty[]`、`IsInGame`（打歌中）、`MusicTrackNumber`（第幾首）。
- `GamePlayManager.Instance.GetGameScore(player, -1)` → `GameScoreList`：判定數（`CriticalNum`、`PerfectNum`、`GreatNum`、`GoodNum`、`MissNum`）、`Combo` / `MaxCombo`、`DxScore`、`GetAchivement()`（拼法如此）。
- `NotesManager.Instance(player)`：`GetSessionInfo()`（`musicId`、`difficulty`、`notesData`）、`getPlayFirstMsec()` / `getPlayFinalMsec()`；靜態 `GetCurrentMsec()`。
- 判定入口：`JudgeResultSt.UpdateScore(int monitorIndex, NoteScore.EScoreType type, NoteJudge.ETiming timing)`，`NoteJudge.ConvertJudge(timing)` → `NoteJudge.JudgeBox`（Critical / Perfect / Great / Good / Miss）。
- 版本：`MAI2System.SystemConfig.Instance.config.displayVersionString`。
- `AssetManager`：`GetJacketTexture2D(name)` / `GetJacketThumbTexture2D(name)`；傳 int 版本內部會呼叫 `GetMusic(id)`，被其他 mod 改寫後可能拿不到圖，直接傳資源名比較穩。
- 收藏品 / 伙伴：`DataManager.GetPartners()`（`Safe.ReadonlySortedDictionary<int, PartnerData>`）、`CollectionData.IsHave`、`AssetManager.GetNaviCharaPrefab(id)` / `GetPartnerTexture2D(id)`、結算畫面伙伴 `NavigationCharacter`（`ResultMonitor` 管理）、伙伴語音 `SoundManager.GetPartnerVoiceCueName(voiceID)`。細節見 [08](08-加入自訂內容.md)。
- 玩家存檔在網路物件（`Net.VO.Mai2.UserDetail`）與內部物件（`Manager.UserDatas.UserDetail`）之間經 `VOExtensions.Export(...)` 轉換，可以在這裡攔截「什麼會上傳伺服器」。
- DX PASS 讀卡畫面：`CodeReadProcess`、`CodeReadMonitor`；卡片資料 `CardData` / `CardTypeData` / `CardCharaData`。細節見 [08](08-加入自訂內容.md)。

## 選曲分類：人氣排行榜（反編譯 1.70）

- 資料：`MusicRankingManager.Initialize()`（在 `AdvertiseProcess` 呼叫）取 `OperationManager.GetMusicRankingList()`（伺服器下發），沒有或無效時改用 `DataManager.GetMusicOffRankings()`（本機預設），最多 50 首，只留 `EventManager.IsOpenEvent` 的歌。
- 分類顯示：`MusicSelectProcess.registerMusic` 只在「有任何已登入玩家 `UserData.Detail.HighestRating < 4000`」時，才把有排名的歌加進 `_combineRankingDataList`；清單是空的，分類就不會插入（`GetMusicGenre(2)`）。活動模式（`GameManager.IsEventMode`）和 ID ≥ 100000（宴會場）不會列入。
- 所以 Rating 曾經到過 4000 的帳號看不到這個分類，GUEST 和新帳號才看得到。
- **不能用設定改**：4000 是程式裡的數字（IL 常數，沒有具名常數），剛好等於 Rating 黃色框的門檻（`RateColorIDEnum` Yellow1 = 4000；`MusicSelectInfoMonitor` 的「Rating 對象曲」提示也用 `rating >= 4000`）。伺服器的 `GameSetting`、`GameRanking` 都沒有相關欄位，選項包 XML 和 AquaMai.toml（1.70 這台）也沒有。只能用 Harmony：暫時改 `HighestRating`，或用 Transpiler 換掉這個常數。
