# 02 接入遊戲的方法

## 1. Harmony 補丁（最主要）

MelonLoader 會自動套用 mod 組件裡所有 `[HarmonyPatch]` 類別。想自己控制時有三種寫法：

```csharp
// 1. 整個組件不要自動套用, 自己挑類別 (MaiL2d)
[assembly: HarmonyDontPatchAll]
HarmonyInstance.PatchAll(typeof(ModelLoader));

// 2. 自己建 Harmony 實例套用全部 (DxPassCompat)
new HarmonyLib.Harmony("com.dxpass.compat").PatchAll(Assembly.GetExecutingAssembly());

// 3. 逐一手動掛, 可依設定決定掛不掛 (點歌台的崩潰保護)
harmony.Patch(method, prefix: ..., postfix: ..., finalizer: ...);
```

跨版本容錯時，不要在屬性裡寫死型別（型別不存在時整個組件會載入失敗），改用名稱查找再手動掛：

```csharp
var type = AccessTools.TypeByName("Process.ModeSelect.ModeSelectProcess");   // 找不到回 null
var m = type == null ? null : AccessTools.Method(type, "OnStart");
if (m != null) harmony.Patch(m, postfix: new HarmonyMethod(typeof(MyMod), nameof(OnStartPostfix)));
// Postfix 的 __instance 宣告成 object, 同一個 Postfix 可以掛在很多種 Process 上
static void OnStartPostfix(object __instance) { var name = __instance.GetType().FullName; }
```

補 getter / setter：`[HarmonyPatch(typeof(X), "Prop", MethodType.Getter)]`，或直接寫方法名 `"get_Prop"`。指定多載：`[HarmonyPatch(typeof(X), "M", typeof(int))]`。

| 類型 | 何時執行 | 用途 |
|---|---|---|
| Prefix | 原方法之前 | 改參數、改 `__instance` 狀態；回傳 `false` 可略過原方法 |
| Postfix | 原方法之後 | 讀結果、記住物件、改回傳值（`ref __result`） |
| Finalizer | 原方法丟例外時（也會在正常結束時呼叫） | 處理或吞掉例外 |
| Transpiler | 編譯時改寫 IL | 改方法內部邏輯（難維護，盡量少用） |

### 例：在選曲畫面開啟 / 關閉時記住物件（點歌台）

```csharp
[HarmonyPatch(typeof(MusicSelectProcess), "OnStart")]
internal static class Patch_SelectOnStart
{
    private static void Postfix(MusicSelectProcess __instance) => SelectDriver.Capture(__instance);
}

[HarmonyPatch(typeof(MusicSelectProcess), "OnRelease")]
internal static class Patch_SelectOnRelease
{
    private static void Postfix() => SelectDriver.Release();
}
```

> `OnStart` / `OnRelease` 會按玩家人數各觸發一次（1P/2P），同一個實例會進來兩次，記得去重。

### 例：攔截播放、改播另一個音效（冰冰冰正解音切換）

```csharp
[HarmonyPatch(typeof(SoundCtrl), "Play")]
internal static class AnswerCueRoutingPatch
{
    [HarmonyPrefix]
    private static void Prefix(SoundCtrl.PlaySetting setting)
    {
        // 正解音 = 第 0 號音效庫(Mai2Cue)的第 88 號音效
        if (setting != null && setting.AcbID == 0 && setting.CueIndex == 88 && 開啟替換)
            setting.AcbID = 6;      // 改從自己載入的第 6 號音效庫播
    }
}
```

### 例：Finalizer 防閃退（原作「崩潰保護」）

```csharp
// 手動掛: 給遊戲的某個方法加 finalizer, 出錯時記一筆並吞掉例外
var ghost = AccessTools.Method(typeof(Process.PlInformationProcess), "RestoreGhost", new[] { typeof(int) });
if (ghost != null)
    harmony.Patch(ghost, finalizer: new HarmonyMethod(AccessTools.Method(typeof(CrashGuard), "RestoreGhost_Finalizer")));

static Exception RestoreGhost_Finalizer(Exception __exception)
{
    if (__exception != null) MelonLogger.Warning("吞掉 RestoreGhost 的例外: " + __exception.Message);
    return null;   // 回傳 null = 吞掉; 回傳 __exception = 照樣丟出
}
```

> ⚠ 吞掉例外會讓遊戲帶著錯誤狀態繼續跑（例如選曲列表變空）。原作 v1.0.4 起把它改成預設關閉。

## 2. 讀寫私有成員

| 方法 | 寫法 | 特點 |
|---|---|---|
| Harmony 參數注入 | 補丁參數寫 `__instance`、`___欄位名`（三個底線 + 欄位名）；原方法參數用同名，或用位置 `__0`、`__1` | 最簡單，只能在補丁裡用 |
| `AccessTools.FieldRefAccess` | 取得欄位的 ref 存取器 | 有型別、快，欄位不存在會明確報錯 |
| `AccessTools.MethodDelegate` | 把私有方法變成委派 | 呼叫私有方法最快的方式 |
| 一般反射 | `GetField` / `GetMethod` + `GetValue` / `Invoke` | 最有彈性，但慢，出錯要到執行時才知道 |

### `HarmonyLib.Traverse`（DxPassCompat、MaiL2d）

```csharp
var list = Traverse.Create(__instance).Field("_readCardChainList").GetValue<ReadCardChainList>();
```

不用先宣告存取器，寫起來最短；效能接近反射，適合不在每幀呼叫的地方。

### 參數注入（扫码点歌）

欄位名本身以底線開頭（`_combineMusicDataList`），所以參數名是 `___` + `_combineMusicDataList` = 四個底線：

```csharp
[HarmonyPostfix, HarmonyPatch(typeof(MusicSelectProcess), "OnStart")]
public static void OnStart(MusicSelectProcess __instance,
    List<ReadOnlyCollection<MusicSelectProcess.CombineMusicSelectData>> ____combineMusicDataList,
    SequenceBase[][] ____subSequenceArray,
    MusicSelectProcess.SubSequence[] ____currentPlayerSubSequence)
{ ... }
```

### FieldRefAccess / MethodDelegate（點歌台）

```csharp
var refSubSeq = AccessTools.FieldRefAccess<MusicSelectProcess, global::Process.SubSequence.SequenceBase[][]>("_subSequenceArray");
var refCurSeq = AccessTools.FieldRefAccess<MusicSelectProcess, MusicSelectProcess.SubSequence[]>("_currentPlayerSubSequence");
var syncNext  = AccessTools.MethodDelegate<Action<MusicSelectProcess, MusicSelectProcess.SubSequence>>(
                    AccessTools.Method(typeof(MusicSelectProcess), "SyncNext"));

var cur = refCurSeq(process);                                       // 讀
syncNext(process, MusicSelectProcess.SubSequence.Difficulty);       // 呼叫遊戲自己的切畫面
```

> `global::Process.SubSequence` 要寫完整：遊戲有一個全域命名空間也叫 `Process`（見 [05 踩坑紀錄](05-踩坑紀錄.md)）。

## 3. 直接使用遊戲的管理器

| 物件 | 用途 |
|---|---|
| `Singleton<Manager.DataManager>.Instance` | 曲目、譜面、分類、段位等全部資料；`IsLoaded()` 判斷是否載入完 |
| `Singleton<UserDataManager>.Instance.GetUserData(i)` | 玩家資料；`IsEntry` 是否有登入 |
| `GameManager`（靜態） | 例如 `SelectMusicID`、`SelectDifficultyID` |
| `GamePlayManager` | 打歌中的分數、Combo、判定數 |
| `MusicSelectProcess` | 選曲畫面狀態與操作（見 [03](03-遊戲內部結構.md)） |
| `Singleton<SoundCtrl>.Instance` / `SoundManager` | CRI 音效：`LoadCueSheet`、`Play` |
| `AssetManager.Instance()` | 封面等圖片：`GetJacketTexture2D`、`GetJacketThumbTexture2D` |

## 4. 每幀邏輯與協程

- `OnUpdate` 在遊戲主執行緒，每幀呼叫。外部執行緒（網頁、網路）要做的事先排隊，在這裡取出執行。
- 需要「下一幀再做」時，借遊戲畫面上的 `MonoBehaviour` 起協程：

```csharp
monitor.StartCoroutine(NextFrame());   // monitor = 某個 MusicSelectMonitor

static IEnumerator NextFrame()
{
    yield return null;                                  // 等一幀, 跟遊戲當幀的 Update 錯開
    syncNext(process, MusicSelectProcess.SubSequence.Difficulty);
}
```

## 5. 輸入

- 鍵盤：`UnityEngine.Input.GetKeyDown(KeyCode.F8)`（要參考 `UnityEngine.InputLegacyModule`）。
- 機台按鈕：遊戲有自己的 `InputManager`（`InputManager.ButtonSetting.Button04` 等），遊戲本身用 `SetInputLockInfo(player, ms)` 鎖輸入。

## 6. 載入額外資源

- 音效：`SoundCtrl.LoadCueSheet(id, 路徑不含副檔名)` 載入自己的 `.acb/.awb`，再用 Prefix 把特定音效轉向它（見 [04](04-音效系統.md)）。
- 圖片：遊戲貼圖多半來自 AssetBundle、不可讀；要輸出時用 `RenderTexture` + `ReadPixels` 回讀再 `EncodeToPNG`（全部在主執行緒做）。
- 自己的檔案：放在 `Mods\你的mod名\` 底下；路徑可用 `MelonEnvironment.ModsDirectory`。
