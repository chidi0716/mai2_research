# 08 加入自訂內容（收藏品、卡面、模型、語音）

整理自 MaiL2d（Live2D 旅行伙伴）與 DxPassCompat（DX PASS 卡面）的做法：怎麼在**不改遊戲資料、不污染伺服器存檔**的前提下，把自己的東西塞進遊戲。

## 1. 用「遊戲不會用到的 ID」代表自訂項目

| mod | 自訂項目 ID | 判斷方式 |
|---|---|---|
| MaiL2d | **負數**：第 i 個模型 = `-1 - i` | `id < 0` 就是自訂，`id >= 0` 交還給遊戲 |
| DxPassCompat | **9000000～9009999**：第 i 張卡 = `9000000 + i` | `id - 9000000` 在範圍內就是自訂 |

所有相關的取資料方法都加 Prefix：自訂 ID 就回傳自己的資料並 `return false`（略過原方法），否則 `return true` 照原流程。

```csharp
[HarmonyPrefix, HarmonyPatch(typeof(AssetManager), "GetNaviCharaPrefab")]
public static bool GetNaviCharaPrefab(int id, ref GameObject __result)
{
    if (id >= 0) return true;               // 遊戲自己的
    __result = ModelStore.GetModel(id).Prefab;
    return false;                           // 自訂的: 直接給, 不跑原方法
}
```

## 2. 把自訂項目加進遊戲的資料表

MaiL2d 在 `DataManager.GetPartners()` 的 Postfix 裡，複製原本的表再加上自訂的伙伴（結果快取起來，避免每次都重建）：

```csharp
[HarmonyPostfix, HarmonyPatch(typeof(DataManager), "GetPartners")]
public static void GetPartners(ref Safe.ReadonlySortedDictionary<int, PartnerData> __result)
{
    // 複製原表 → 對每個自訂模型建一個 Manager.MaiStudio.Serialize.PartnerData
    //   name = new StringID { id = -1 - i, str = 模型名 }, naviChara = new StringID { id = -1 - i }, priority = 100 + sort …
    // → new PartnerData().Init(序列化資料) → 加入字典 → 包成新的 ReadonlySortedDictionary
}
```

再讓「是否持有」永遠為真：Prefix `CollectionData.IsHave`（getter，`MethodType.Getter`），自訂 ID 回傳 `true`。

DxPassCompat 則是把遊戲的 `CardTypeData` 用反射**逐一複製屬性**（呼叫私有 setter）成新物件，再改標題，當作自訂卡的資料。

## 3. 不讓自訂選擇傳到伺服器

遊戲存檔在「網路傳輸物件（DTO）」和「遊戲內部物件」之間轉換，都經過 `VOExtensions.Export(...)`（擴充方法）。MaiL2d 掛兩個方向：

| 方向 | 做法 |
|---|---|
| 伺服器 → 遊戲（`Export(Net.VO.Mai2.UserDetail, ulong userId)` 的 Postfix） | 記住伺服器上原本的伙伴 ID；如果本機有選自訂伙伴，把 `EquipPartnerID` 換成自訂的負數 ID |
| 遊戲 → 伺服器（`Export(Manager.UserDatas.UserDetail)` 的 Postfix） | 如果要上傳的是負數 ID，改回伺服器原本的 ID，並把自訂選擇存在本機 |

本機選擇存在 Unity 的 `PlayerPrefs`（key `MaiL2DUserModel:{userId}`）。效果：自訂伙伴只在本機有效，不會污染帳號存檔；檔案被刪掉時自動退回原本的伙伴。

DxPassCompat 也有類似考量：「全解本地卡面」只在本機顯示，不上傳。

## 4. 載入自訂資源

### Unity AssetBundle（模型、Prefab）

- 遊戲是 **Unity 2018.4.7f1**，自製 AssetBundle 要用同版本的 Unity 編輯器、目標 `StandaloneWindows64` 打包（`BuildPipeline.BuildAssetBundles`）。
- MaiL2d 的模型包 `*.mail2dpack` 就是 AssetBundle（檔頭 `UnityFS`），裡面有名為 `L2dNaviCharaRoot` 的 Prefab，Prefab 上掛 `ModelMeta` 元件（圖示、名稱、說明、作者、physics3.json、排序）。
- 載入：`AssetBundle.LoadFromFile(path)` → `LoadAsset<GameObject>("L2dNaviCharaRoot")`。
- mod 自己需要的資源（材質）也打成 AssetBundle 內嵌在 DLL，用 `AssetBundle.LoadFromStream(GetManifestResourceStream(...))` 載入。

### 原生 DLL

MaiL2d 需要 Live2D 的 `Live2DCubismCore.dll`：內嵌在 mod 裡，第一次啟動時寫到 `Sinmai_Data\Plugins\`。

### 圖片

DxPassCompat：`File.ReadAllBytes` → `new Texture2D(2, 2)` + `ImageConversion.LoadImage` → `Sprite.Create(...)`，結果快取。

### 語音（CRI ACB）

- 遊戲取得伙伴語音音效庫名稱的方法：`SoundManager.GetPartnerVoiceCueName(int voiceID)`。MaiL2d 對自訂 ID 回傳**檔案路徑**（不含副檔名），遊戲就會載入同名的 `.acb/.awb`。
- 官方伙伴語音 ACB 結構（範例 `Voice_Partner_000001`）：92 個音效，名稱 `VO_000080`、`VO_000081`…`VO_000254`，HCA 編碼，聲音放在 stream AWB。
- 製作工具：ACE（<https://github.com/LazyBone152/ACE>，v1.1.0.0）。不要的語音刪 Track，**不要刪 Cue**，以免 Cue ID 錯位。

### 本機資源資料夾慣例

| mod | 位置 |
|---|---|
| MaiL2d | `Package\LocalAssets\MaiL2dModels\*.mail2dpack`（+ 同名 `.acb/.awb`） |
| DxPassCompat | `Package\LocalAssets\dxpass\*.png`（建議 768:1052） |

## 5. 伙伴（旅行伙伴）動畫

結算畫面的伙伴（`NavigationCharacter`，`ResultMonitor` 管理）用 Animator 狀態機。手冊整理的遊戲狀態名：

| 狀態 | 時機 |
|---|---|
| `Navi_Fun_Loop_02` | Clear 時的閒置動畫 |
| `Navi_Fun_Start` | 被觸摸時；友人對戰勝利後一開始也會播 |
| `Navi_Sad_01` | 沒有 Clear 時 |

Clear 包括一般歌曲 80% 以上與友人對戰勝利。伙伴出現時先進預設狀態，按「跳過」後才跳到對應的閒置動畫。

MaiL2d 額外提供兩個 Animator 參數：`IsClear`（bool，Postfix `ResultMonitor.SetStartData` 設定）、`Random`（0～1 浮點數，開始與被觸摸時設定，Prefix `ResultMonitor.TouchPartnerCharacter`），讓模型作者做隨機動作。

### maimai-ngo（PartnerLive2D）的做法

- 導航角色動畫的入口是 `NavigationCharacter.Play(NavigationAnime type, float normalizedTime)`。`NavigationAnime` 的值有 `Default`、`Welcom`（原名拼錯）、`FunStart`、`FunStartLoop`、`Sad01`（反編譯）。把這幾個狀態對應到自己的動作，就能接管所有畫面的導航角色。
- 只在**裝備中的搭檔**（`UserDetail.EquipPartnerID`）有自訂資料時，才在結算畫面換掉。
- 搭檔房間：`PartnerRoom.CreatePartner(int partnerId)`。
- 收藏清單的圖示：掛 `AssetManager.GetPartnerTexture2D(int)`。清單是用 ID 取圖，`(string)` 版本會被內聯，掛在上面不會觸發，見 [10](10-資源與選項包.md#3-貼圖怎麼載入)。
- 新搭檔用選項包的 `A500\partner\partner<ID>\Partner.xml` 加進資料表（`isDefault = true` 讓每張卡都擁有），不用 Harmony 注入。
- 新的 `naviChara` ID 沒有 Prefab，遊戲會退回原版角色，要用 `CanvasGroup`（alpha 0）把它藏起來。
- Live2D 用遊戲內建的 shader 畫進 RenderTexture：`Sprites/Default`、`UI/Default`（遮罩）、Legacy Particles（混合模式）。遊戲沒有 Standard shader，也不能新編 shader。（NGO 實測）
- 逐格精靈：用 BC7 原始資料，`LoadRawTextureData`（由下往上），格式和 [10](10-資源與選項包.md#4-動態銘牌ngoplates-的做法) 的動態銘牌一樣。用 `Sprites/Default` 畫時要設 `_RendererColor` 和 `_Flip`，不然什麼都不會畫出來。（NGO 實測）

### 不寫 Harmony 的加法

收藏品（銘牌、稱號、icon、frame、搭檔）可以全部用選項包 XML 加入，做法見 [10](10-資源與選項包.md)：開一個新的 `Axxx` 資料夾，放 XML + 圖。用 Track 條件，打一首歌就會解鎖。這和第 1～3 節不同：資料會走遊戲正常的取得和上傳流程。

## 6. DX PASS 相關（DxPassCompat）

- 讀卡畫面：`CodeReadProcess`（`OnStart`、`GetUserCard`、`GetEnableUserCard`、`GetReadCard`、`GetCardTypeData`、`IsValidCard`、`IsInPeriod`）與 `CodeReadMonitor.Scroll`、`ReadCardChainList.Deploy`（卡片列表）。
- 卡片資料：`CardData`（`IsDisable`、`enableVersion`）、`CardTypeData`、`CardCharaData`；玩家卡片 `UserData.CardList`（`UserCard`：`cardId`、`cardTypeId`、`charaId`、`startDate`、`endDataDate`）；`UserExtend.UpsertCardLog`、`SelectedCardList`。
- 卡種：2 = Bronze、3 = Silver、4 = Gold、5 = Platinum、6 = Freedom。
- 舊卡不顯示的原因之一是 `enableVersion` 太舊，mod 在 getter 的 Postfix 用反射把 `StringID.id` 改成 12。
- 要在「加入遊戲」時於 8 號鍵的設定裡打開 DXPASS，才會進入 DX PASS 畫面。
